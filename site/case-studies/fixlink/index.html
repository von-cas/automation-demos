§ 02

The problem.

Who has it · what it costs

Support agents answer the same “how do I…” question every week. The usual reply is a wall of text or a screenshot pasted into chat. Customers lose their place halfway through, and the agent explains it again.

Screenshots also leak emails, card numbers and API keys. Blurring them by hand is slow, so it gets skipped when the queue is long.

Help-center tools exist, but they are built for documentation teams. An agent in the middle of a ticket needs something faster: show the fix once, get a clean link, and paste it into the reply.

§ 04

How it works.

Record → blur → publish → follow → feedback
  1. Record. The extension’s side panel records clicks and screenshots while I do the fix on my own screen. Emails, card numbers and keys are blurred in the screenshot before it leaves the browser.
  2. Review. The web editor turns the capture into steps. I fix the wording, reorder steps, mark up a screenshot or redo one step. An optional AI pass tidies the writing and checks the screenshots for anything the blur missed.
  3. Publish. The guide gets a link under the company’s handle, in the company’s brand color, like usefixlink.com/<handle>/<guide>.
  4. Share. I copy the link, or a ready-made reply that includes it. Teams can also embed a guide on their site or group guides into a searchable help collection.
  5. Learn. At the end the customer taps “Yes, solved” or “Not yet”. The results page shows which guides work and which ones need a rewrite.
§ 05

Reliability.

What can fail · what happens then
Failure modes and how FixLink handles each
If this failsWhat happens
A screenshot leaks a customer’s email or cardBlur runs in every frame and inside shadow DOM, with no match cap. A frame the extension can’t read is blurred whole. The blur stays solid to the image edges. A real Chrome test found an edge leak, and I fixed it.
Two edits collideChanges that depend on the current guide, like AI polish or a screenshot upload, run under a row lock and merge field by field. An edit saved in the meantime is kept.
A big guide fails to saveThe web app and the extension share one size budget. Autosave sends only the screenshots that changed, and splits a save that would pass Vercel’s 4.5 MB request limit.
One company reads another’s dataSupabase row-level security is on for every app table, and the public key’s table grants are revoked. Every admin page checks the role before it loads data.
Someone fakes a Google identityThe Google account ID comes only from verified identities, never from profile fields a user can edit.

How it’s tested

32 web and store tests run against a real Postgres database, including a concurrency test for two editors. 12 recorder privacy tests load the real extension in Chrome and check that every email in the capture is unreadable. Each security fix shipped with a test that fails on the old code.

§ 07

Tech and decisions.

Architecture · why this, not that
Web appNext.js 16 (App Router) on Vercel
Data + sign-inSupabase Postgres and Auth, with row-level security
RecorderChrome extension (Manifest V3) with a side panel
Shared codeOne TypeScript package for capture-to-guide logic, blurring and size limits
AIAn OpenAI-compatible client, on Ollama Cloud or OpenRouter
  1. Blur in the browser, not on the server. Private text is hidden before the screenshot is uploaded, so FixLink never stores the raw image.
  2. One page for people and AI. Every step stays in the server HTML. The same guide works for a customer on a phone and for an AI assistant fetching it, with no separate copy to keep in sync.
  3. The customer’s brand, not FixLink’s. Guides wear the company’s color, so the customer feels they are still with the company they asked for help.
  4. Light pages over a full brand background. I tried a full-bleed brand color and dropped it because it was tiring to read. The color now sits on the title, progress bar and main button.
  5. One size budget, checked in the build. The extension and the web app read the same limits, and a check fails the build if they drift apart.
